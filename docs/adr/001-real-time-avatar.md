# ADR 001: Real-Time Audio-to-Face Pipeline and Gesture Synchronization

## Status
Accepted

## Context
Mentora originally relied on pre-rendered videos generated by `Wav2Lip` via the backend python scripts. While high fidelity, this approach is extremely slow (high latency), cannot be used interactively in a two-way real-time conversation, and incurs heavy server GPU costs. We needed a new architecture to support a real-time "AI Teaching Avatar" capable of interactive voice chat.

## Decision
We decided to adopt a client-side WebGL approach paired with streaming backend APIs:
1. **Frontend Rendering (Three.js):** Moving from backend MP4 rendering to frontend 3D rendering (WebGL/Three.js) enables 60FPS interactivity at zero server cost.
2. **STT (Speech-to-Text):** We utilize the browser's native `SpeechRecognition` API (Web Speech API) via a Push-To-Talk mechanism. This bypasses the need to stream and process heavy audio blobs on the backend, reducing latency to milliseconds.
3. **Procedural Lip Sync (Web Audio API):** Instead of generating exact visemes via expensive ML models (e.g. Rhubarb), we use the `AnalyserNode` to extract byte frequency data from the incoming TTS audio stream. We map the normalized volume directly to the 3D avatar's jaw bone/mouth scale. This provides a highly convincing "muppet-style" lip sync with near-zero latency and computational overhead.
4. **Gesture Synchronization:** The LLM is instructed via the System Prompt to output inline bracket tags (e.g., `[smile]`, `[point_board]`). The backend `utils_gesture.py` parser strips these out, calculating their character index. The frontend matches the TTS audio playback time (estimating ~15 chars/sec) to this index, triggering procedural skeletal animations exactly when the word is spoken.

## Consequences
### Positive
- Latency between user speech and avatar response is drastically reduced.
- Server costs drop significantly (no video encoding or GPU-heavy lip sync required).
- Unlocks infinite, continuous conversational loops.

### Negative
- Client device performance matters (requires WebGL).
- Lip sync is amplitude-based, not viseme-accurate (shapes don't perfectly match vowels).
- The gesture timing heuristic (15 chars/sec) may drift slightly on very long responses.
